## Notes

- The meeting is being recorded.  Our code of conduct applies to this meeting.  https://github.com/Ecma-TC54/tg2/blob/main/CODE_OF_CONDUCT.md.
- Intro by Philippe, preliminary matters, proposed agenda.
- Minutes from last meeting: approved.
- Summary
  - The group met to finalize VERS and PURL specifications and documentation for upcoming Ecma standardization cycles.

    **VERS Specification Design (1st Ecma Edition)**

    - TG2 group approved:
      - The current minimalist approach for the VERS type definition schema.
      - Eliminating the explicit equals operator for VERS constraints to support a single canonical equality form.
      - Requiring encoding for whitespace in a version element of a VERS constraint.
    - The plan for ECMA submission is to deliver a set of markdown documents to Steve Springett for conversion to Ecma format with the ecmarkup tool.

    **PURL Specification Enhancements (ECMA-427 2nd Edition)**

    - TG2 group approved:
      - Adding clause 5.7 to clarify requirements for validation for a PURL where the PURL type is registered or not.
      - Adding text to clause 5.1 to describe how a PURL should be a locator.
      - Adding Recommended Qualifiers as informative Annex B.
      - Adding the ABNF grammar as informative Annex C.
    - The plan for ECMA-427 2nd Edition is to consolidate pull requests from the `purl-spec` repository to create PRs for submission to the official ECMA-427 repository.

    **Website and Document Delivery**

    - Updates to the production www.packageurl.org website were finalized to prevent document duplication and resolve formatting issues.
- **Previous Meeting Minutes and Announcements**: Philippe Ombredanne opened the Ecma TC54-TG2 task group meeting under the TC54 code of conduct, noting that the session was recorded strictly to produce accurate meeting minutes. The minutes from the August 14 meeting were approved as published online. Additionally, Philippe Ombredanne announced that the Fedora project adoption of package URL was approaching finalization.
- **Project Plans and VERS Draft Overview**: Michael Herzog reviewed project tracking sheets, milestones, and pull requests, reporting that draft Markdown and JSON files for Annex A and parallel PURL specifications have been created and renamed to align with website conventions. Michael Herzog noted that the proposed VERS specification draft is lightweight, particularly concerning the VERS type definition.
- **VERS Type Schema and Minimalist Design Philosophy**: Philippe Ombredanne and Michael Herzog addressed concerns regarding the minimal detail present in the VERS type definition schema proposal. Philippe Ombredanne noted that the schema is minimalist rather than incomplete to ensure backward compatibility, proposing that structured definitions be developed in parallel for a 2nd edition (June 2027 Ecma cycle) rather than implementing untested complexity within the schema. Michael Herzog concurred with this minimalist and do-no-harm approach, noting there are approximately six to seven active implementers.
- **VERS Schema Constraints and Equality Operators**: Michael Herzog raised open issues in the draft VERS type definition schema, proposing to change the terminology from "VERS ranges" to "VERS constraints" to reduce confusion. Michael Herzog also questioned whether to maintain two methods for expressing equality ('vers:npm/1.2.3' versus 'vers:npm/=1.2.3)'. Philippe Ombredanne suggested supporting only a single canonical form by removing the explicit equals operator, requiring backward compatibility transformations, and Steve Springett agreed with this direction.
- **Whitespace Handling and Percent Encoding in VERS**: Michael Herzog and Philippe Ombredanne discussed how to handle whitespace and odd characters in version strings to prevent ambiguities. Steve Springett and Philippe Ombredanne agreed that ecosystems should strictly reject fuzzy inputs and require percent-encoding for spaces and special characters, acknowledging that enterprise software usage sometimes involves irregular version formats.
- **VERS Type Examples, Schema Bugs, and Versioning**: Michael Herzog and Philippe Ombredanne reviewed schema examples comparing native ranges to VERS constraints to ensure precise comparisons. Philippe Ombredanne identified a bug on line 111 (referring to vers-type-definition.schema-0.2.json) regarding misplaced example structures, which they committed to correcting. Regarding schema versioning, Michael Herzog proposed bumping the version number to 1.0 upon submission to Ecma, keeping potential ISO fast-track requirements in consideration.
- **Package-URL Site Folders and Schema Draft Versions**: Michael Herzog announced the creation of new repository folders under www.package-url.org including specific directories for `vers-types/` and `purl-types/` to make definition files directly accessible. Philippe Ombredanne suggested adding a redirect from the old `types/` directory to `purl-types/`. Furthermore, Michael Herzog noted that the JSON schema will utilize draft 2020-12, following requests from Immanuel, Thomas Schmidt, and the CSAF group.
- **PURL Specification Updates and Known Types Section**: Michael Herzog reviewed PURL specification updates and presented a proposed new clause 5.7 regarding known types. The proposal states that if a PURL type is registered, a PURL is invalid if it fails to conform to the corresponding type definition; if it is unregistered, it is valid if it conforms to the PURL spec stated rules, and implementations should report a warning. Steve Springett reviewed the language and expressed agreement.
- **PURL Location Capability and Repository URLs**: Michael Herzog proposed moving the discussion on locator capability to the bottom of clause 5 to clarify that locator functionality is separate from formatting validation. Philippe Ombredanne suggested using "should" rather than "may" to promote default repository locations for PURL types, and Jan Kowalleck noted this aligns with discussions alongside IANA and URL schemes.
- **Git and GitHub Actions Types in PURL**: Philippe Ombredanne and Michael Herzog discussed version control URLs, noting that the 'git' PURL type has already been approved and that separate discussions regarding a proposed 'github-action' PURL type are actively managed among interested parties like Jon Moroney.
- **Style Consistency and Spelling Conventions**: Michael Herzog raised concerns regarding spelling consistency across documentation, noting discrepancies between Oxford English spelling and North American variants, such as "normalization" with an "s" versus a "z" and "programming" with one or two "m"s. Jan Kowalleck and John Horan participated in reviewing these consistency adjustments to satisfy ECMA standards filters.
- **PURL Recommended Qualifiers and ABNF Grammar**: Michael Herzog reviewed Annex B updates regarding recommended PURL qualifiers. Jan Kowalleck reported that the PURL ABNF grammar specification has been stable for two weeks and is ready for review, prompting Michael Herzog to format it as Annex C while adjusting introductory phrasing to avoid recursive use of the term "canonical" within standard text. Finally, Jan Kowalleck and Michael Herzog discussed appropriate file naming conventions for draft grammar files to prevent website build conflicts.
- **Website Specification Versioning and Formatting Fix**: Michael Herzog discussed a workflow learning regarding PURL specifications, noting that previous processes inadvertently published draft changes as the specification rather than preserving the 1st Edition content. Michael Herzog explained that a document duplication problem was fixed by eliminating custom documents without Ecma numbers formatting, ensuring the site matches the official standard. Michael Herzog stated that they can push these updates from the GitHub.io staging website to the production website today.
- **Website Layout and Submenu Display**: Philippe Ombredanne questioned a large white space column visible on the left side of the core specification on Michael Herzog's machine. Michael Herzog explained that the space is reserved for an index table or submenu which can be suppressed under certain conditions, and they agreed to deal with the layout detail later.
- **Standard Naming Conventions**: Michael Herzog clarified the naming rules for the standard, noting that lowercase titles designate older versions for website use, while capitalized titles match official Ecma names.
- **Upcoming Deliverables and Work Plan**: Michael Herzog outlined the schedule, stating that by Monday they aim to have a full set of draft documents ready for Ecma. For VERS, Michael Herzog explained that they will prepare a package to send to Steve Springett to assist with conversion with ecmarkup, while for PURL the task involves consolidating actual pull requests and creating a corresponding set of pull requests to spec.html in the official ECMA-427 repository. Philippe Ombredanne and Steve Springett confirmed they had no additional items to add before leaving the call.
- **Grammar Reviews and Document Structuring**: Michael Herzog expressed gratitude to Jan Kowalleck for help with his work on the PURL ABNF grammar, mentioning that he (Michael Herzog) and John Horan recently reviewed the regular ABNF grammar.
- The meeting was adjourned.
