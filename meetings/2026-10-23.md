- **Approval of Previous Meeting Minutes**: Philippe Ombredanne opened the TC54-TG2 meeting, reminding participants of the code of conduct available in the TC54 repository. Philippe asked for any objections to the September 11th minutes, and hearing no objections, the minutes were approved.
- **Meeting Agenda and FOSSapalooza Event Announcement**: Michael Herzog outlined two agenda items regarding review comments on the standards and the software ID decision documents. Philippe Ombredanne announced a joint event called "FOSSapalooza" to be held by OWASP and OpenChain on the day before FOSDEM to celebrate PURL, CycloneDX, and other TC54 and related standards.
- **Review of PURL and VERS Documentation Issues**: Michael Herzog discussed approximately 10 issues and pull requests raised by Aki Rose concerning PURL and VERS, focusing on formatting, indentation, and informative annex restrictions where "shall" must be replaced with "should". Michael Herzog noted discrepancies stemming from the unofficial `TOOLS-011.docx` document and single-quote conventions for values versus code styles. Michael Herzog and John Horan committed to resolving these items and pinging Aki Rose for comments by the end of the day.
- **Software ID Decision Document and Mandatory Domain Qualification**: Michael Herzog and Philippe Ombredanne introduced the software ID decision document, highlighting a core substantive change: making a domain a mandatory component at the start of every software ID namespace to simplify proposals. Michael Herzog explained that this structure avoids prefix ambiguities and allows `packageurl.org` to act as a shared service alongside other domains, supporting flexible naming conventions determined by publishers ranging from open source to commercial entities.
- **Infrastructure and Hosting for Package-URL Files**: Michael Herzog and Steve Springett discussed how files would be served using a `.well-known/purl` path pointing to raw files hosted directly on infrastructure rather than GitHub, leveraging content delivery networks like Fastly or Cloudflare as suggested by Philippe Ombredanne. Steve Springett questioned infrastructural readiness and the separation of the human website from file hosting domains, but Philippe Ombredanne and Steve Springett ultimately agreed that splitting domains would cause unnecessary confusion.
- **Registry Directory Structure and Package Type Definitions**: Addressing concerns raised by Steve Springett regarding potential abuse cases like automated crawling of all package PURLs, Philippe Ombredanne outlined mitigation strategies including rate limiting, registry cloning options, and providing an LLM text file. Philippe Ombredanne shared a newly pushed registry structure starting with package types like software ID, followed by domain aggregations and leaf nodes for package manifests and version lists, utilizing schemas consistent with package type definitions.
- **Version List Formatting and Stream Parsing Considerations**: Steve Springett raised concerns about memory consumption when parsing extremely long version arrays in JSON, suggesting JSON Lines (aka 'jsonl' – https://jsonlines.org/) or stream parsing. Philippe Ombredanne and Steve Springett evaluated alternative formats, with Philippe Ombredanne suggesting plain text with one PURL per line as the simplest and most efficient approach for version lists, eliminating unnecessary JSON or YAML boilerplate.
- **Software ID Decision Document Sections and Non-Goals**: Michael Herzog reviewed the decision document's structural compliance with templates, covering decision drivers, non-goals such as excluding services and hardware, and alternative approaches like generic types and combined commercial/open source PURLs. Michael Herzog noted that the document includes links to historical issues and outcome summaries and some sections serve as illustrative examples.
- **Structural Mandates and Redirect Handling for Commercial Publishers**: Michael Herzog and Steve Springett discussed whether the `.well-known/purl` file structure should be mandated for all external publishers. Steve Springett emphasized the necessity of explicitly defining how temporary and permanent redirects are handled, noting that large commercial publishers utilizing external enterprise platforms like Adobe Experience Manager will redirect requests rather than hosting files locally. Philippe Ombredanne affirmed that the endpoint must return valid JSON following the schema regardless of redirection chains.
- **Approval Process and Next Steps for the Software ID Document**: Michael Herzog and Philippe Ombredanne discussed the path forward for finalizing and approving the decision document through a formal remote TG2 task group vote. Philippe Ombredanne committed to updating examples in the PURL registry repository, after which Michael Herzog and John Horan would review the terminology and finalize editorial changes.
- **Terminology for Domain Owners and Software Publishers**: Michael Herzog and Philippe Ombredanne debated terminology for entities within the standard, establishing "authority" to describe domain owners and "publisher" to describe software owners, moving away from terms like vendor and supplier.
- **Registry Subtype Definitions and Reference URLs**: Philippe Ombredanne and Michael Herzog reviewed an example of a registry subtype definition file (e.g., for `zip.net`) within the PURL registry, discussing how to incorporate homepage references and repository flags while avoiding the complication of core type definition access.
- **Tracking Author Ownership, Contact Information, and Licenses**: Michael Herzog and Philippe Ombredanne debated whether contact information, author ownership, and licenses should be included in PURL type definitions or managed externally. Michael Herzog argued against storing personal contact details and dynamic license data in static type definitions due to privacy and mutability concerns, suggesting that GitHub registration records provide sufficient assertion of identity, while Philippe Ombredanne noted the necessity of public attribution.
- **Maintaining Context and Ownership for Type and Subtype Data**: The underlying problem involved managing context changes for type and subtype data independently of data structures, raising complications regarding authorship, ownership, and control over packages and sub packages. Michael Herzog argued that maintenance processes are complex and require clear direction for authors and owners, while Philippe Ombredanne suggested exploring integration with security.txt by adding a Package-URL field, though noting potential limitations if files are not secret. Philippe Ombredanne further clarified that ownership control specifically applies to type or subtype definitions rather than general code, which Michael Herzog acknowledged. For decisions, Michael Herzog decided to document a question about this in the decision document so they can revisit it later, establishing it as a distinct category of information regarding software ownership and control. Regarding task attribution, Michael Herzog requested the documentation of this question, and they will act as the executor of that documentation task within the decision document.
- **GitHub Registration Process and Contribution Workflow**: The underlying problem focused on establishing how contributions and registrations are managed and documented when the person submitting pull requests differs from the person raising conceptual issues. Michael Herzog explained that the registration process will be handled through GitHub, requiring specific IDs to review and approve pull requests. As an example of normal workflow, Michael Herzog highlighted that Thomas Schmidt frequently raises conceptual issues and discussions, while Immanuel Kunz typically submits the pull requests, a dynamic that Philippe Ombredanne agreed was completely normal. Regarding consensus, Michael Herzog decided that all registration and contribution information will be stored directly in GitHub rather than external systems. For task attributions, Michael Herzog outlined the GitHub storage process, and they specified that contributors like Immanuel Kunz execute the pull requests while individuals like Thomas Schmidt handle conceptual issues.
- **Evaluation of CSAF and Product Identification Standards**: The underlying problem is assessing the complexity and practicality of existing security standards like CSAF for product identification and tracking. Philippe Ombredanne argued that CSAF is complicated, pointing out that product identification helpers like names, product IDs, and Package-URLs are actionable elements, while noting that CPE is missing..
- The meeting was adjourned.
